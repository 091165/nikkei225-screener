# 現行ロジックの調査メモ（2026-10-31 時点）

長期投資ロジック（暴落点ルール）の追加前に、既存の「理想乖離ダッシュボード」がどう計算しているかを整理したもの。
対象コード: `stock_deviation_screener.py`（個別株）、`generate_web_dashboard.py`（Web）、`ideal_deviation_dashboard.py`（指数）、`.github/workflows/*.yml`。

---

## 1. スコア（買いスコア）の計算式

`calc_deviation()` 内で、以下を足し合わせて最後に `min(score, 100)` している。

| 項目 | 条件 | 点 |
|---|---|---|
| (1) -2σへの近さ | `dist_to_2s` ≤ 0（-2σ到達） / ≤ 3% / ≤ 5% / ≤ 10% | 40 / 30 / 20 / 10 |
| (2) -3σ到達 | 乖離率 ≤ -3σ | +5 |
| (3) 配当利回り | 高配当（JP 4% / US 6% 以上） / 基準の75%以上 / 50%以上 | 20 / 12 / 5 |
| (4) テクニカル | 日足25MA上抜け、月足陽転（前2か月陰線→当月陽線）、手法12（月足9MA/24MA GC 等） | 各 +5（最大15） |
| (5) 底値圏 | 上場来高値から半値以下 / 30%以上下落 | 10 / 5 |
| (6) PBR | 0 < PBR < 1 | +5 |
| (7) 業績 | 増収増益（売上・利益とも +5%超） / 微増（ともにプラス） | 5 / 2 |
| (8) 優良財務 | 自己資本比率 ≥ 50% かつ ROE ≥ 10% | +5 |

- `dist_to_2s` = (現在値 ÷ -2σ到達株価 − 1) × 100。-2σ到達株価 = 25日線 × (1 + -2σ乖離率/100)
- **理論上の最大は 105 点（100 でカット）だが、実際は 0〜65 程度に収まる**。2026-10-31 の全421銘柄で 最小0 / 中央値17 / 平均19.6 / 最大65。理由：
  - 配点の大きい (1) 40点 と (3) 20点 を同時に満たす銘柄が少ない（-2σ到達21銘柄、高配当15銘柄）。
  - (4) の「日足25MA上抜け」は「25日線を上に抜けた」状態なので、-2σ（25日線の大きく下）にいる状態と同時には起きにくい。
  - (5) 半値以下（53銘柄）と (8) 優良財務（174銘柄）も、-2σ到達と重なる銘柄は限られる。
- 既存スコアは Excel・Web（スコア列・上位カード）の両方に表示されている。

## 2. 乖離率と -2σ の算出方法

- **移動平均**：25日の単純移動平均（`SMA_PERIOD = 25`）。終値ベース。
- **乖離率**：(終値 − 25日SMA) ÷ 25日SMA × 100
- **統計期間**：`yf.Ticker(t).history(period="max")` で取れる**全期間の日足**（直近N年ではない）。銘柄により 371〜16,293 日。
- **算出方法**：**平均 ± k × 標準偏差**（パーセンタイルではない）。
  - -2σ = mean − 2·std、-3σ = mean − 3·std、+2σ / +3σ も同様。
  - std は pandas の標本標準偏差（ddof=1）。
- 指数ダッシュボード（`ideal_deviation_dashboard.py`）も同じ方式（25日SMA・全期間・平均±k·std）。

## 3. ゾーン区分

コード上は **6区分**（Web表示名は `generate_web_dashboard.py` の `ZONE_JP`）。判定は上から順に評価。

| 内部名 | 表示名 | 条件 |
|---|---|---|
| STRONG BUY | 強い買い | 乖離率 ≤ -3σ |
| BUY ZONE | 買いゾーン | 乖離率 ≤ -2σ |
| MILD DIP | 軽い押し目 | 乖離率 ≤ 0 |
| NEUTRAL | 平常圏 | 乖離率 ≤ +2σ |
| OVERBOUGHT | 過熱 | 乖離率 ≤ +3σ |
| EXTREME HIGH | 極端な高値 | 乖離率 > +3σ |

※ 指示書では5区分とあるが、実際は「極端な高値」を含む6区分。

## 4. 「52週」列と「ATH下落」列

- **52週（`week52_pos`）**：52週レンジ内の現在位置（%）。
  `(現在値 − 52週安値) ÷ (52週高値 − 52週安値) × 100`
  52週高値・安値は yfinance の `info["fiftyTwoWeekHigh"/"fiftyTwoWeekLow"]`（Yahoo側の値。日足履歴から自前計算はしていない）。0% = 52週安値、100% = 52週高値。
- **ATH下落（`drop_from_ath`）**：`(1 − 現在値 ÷ 上場来高値) × 100`。
  上場来高値は `history(period="max")` の**終値の最大値**。yfinance の `history()` は既定で `auto_adjust=True` なので、**分割・配当調整後の終値**ベース（高値・安値列ではなく終値）。
  - 現在値（乖離率計算に使う最新終値）も同じ調整後系列なので、比較の整合性はとれている。

## 5. データ取得・実行環境

| 項目 | 現状 |
|---|---|
| データ取得元 | yfinance（Yahoo Finance）。株価 `history(period="max")`、`info`（PBR/PER/ROE/負債比率/52週/売上・利益成長率/セクター）、`dividends`、`splits` |
| 取得期間 | 全期間（max）。1銘柄につき `history(period="max")` を**2回**呼んでいる（乖離率用とシグナル用） |
| 配当 | 日米ともCSV（`jp_dividends.csv` / `us_dividends.csv`、`as_of` 列つき）が優先。`as_of` 後の株式分割は自動調整。CSVにない米国株のみ yfinance の直近1年配当 |
| 業績 | `info["revenueGrowth"]` / `info["earningsGrowth"]`（Yahoo が出す直近の前年比1つだけ）。**複数期の決算推移は使っていない** |
| キャッシュ | **なし**。毎回全銘柄・全期間を取り直している |
| 並列化 | なし（逐次処理、50銘柄ごとに2秒スリープ） |
| 銘柄数 | 約421（日経225・ダウ30・NASDAQ100・配当貴族・S&P500高配当、重複除外後） |
| Actions 実行時間 | ジョブ全体 約7〜11分（うちスクリーナー本体 約6〜10分）。`timeout-minutes: 45` |
| 実行タイミング | 個別株 `stock_screener.yml` 平日 07:30 UTC（16:30 JST）、指数 `dashboard.yml` 平日 07:00 UTC（16:00 JST）。どちらも手動実行可 |
| 出力 | `output/stock_deviation_YYYY-MM-DD.{csv,xlsx}`、PNG、`output/docs/{index,us}.html` を **main にコミット**し、`output/docs` を `gh-pages` にデプロイ。CSV/XLSX は毎日増え続ける（XLSX 約0.2MB/日） |

## 6. その他、気づいた点

- 月足シグナル（月足陽転・手法12）は、**確定していない当月の足**も含めて判定している。
- RSI(14) は単純移動平均版（Wilder の平滑化ではない）。
- 業績判定は「直近の前年比」1点だけなので、指示書の条件D（全期で前年比プラス）とは別物。
- 失敗した銘柄はスキップしてログ（`[ERROR]` / `Failed tickers`）に残す。全銘柄失敗時のみワークフローを失敗させる。

## 7. 指示書の仕様と既存ロジックの食い違い

| # | 項目 | 既存 | 指示書（新ロジック） | 提案 |
|---|---|---|---|---|
| 1 | 理想乖離の算出 | 平均±k·σ のみ | σ方式とパーセンタイル方式の両方。既定はパーセンタイル | 既存表示は σ のまま残し、新タブだけ両方計算（既定パーセンタイル） |
| 2 | ゾーン区分 | 6区分（極端な高値あり） | 5区分の記載 | 既存の6区分はそのまま。新タブは独自の判定（長期買い強/長期買い/監視/見送り）を使うので影響なし |
| 3 | 業績データ | `info` の直近前年比1点 | 通期・四半期の複数期推移で判定 | 新タブは `financials` / `quarterly_financials` から別途取得（yfinance は通期4期・四半期5期程度が上限） |
| 4 | 52週・ATH | 52週は Yahoo の `info`、ATH は調整後終値の最大 | 上場来高値は全期間の調整後終値で判定 | ATH の定義は一致。新タブは日足履歴から自前で計算し、`info` には依存しない |
| 5 | データ取得 | 毎回全期間を2回取得、キャッシュなし | Parquet キャッシュ＋差分取得、並列化 | 新ロジック導入時にキャッシュを入れ、既存スクリーナーも同じキャッシュを読むようにすれば、実行時間はむしろ短くできる見込み |
| 6 | 出力の保存先 | 日次 CSV/XLSX を main にコミット | キャッシュはリポジトリ外 | キャッシュは Actions cache に置く。既存の日次CSVコミットは今は変えない |
| 7 | 月足 | 未確定の当月足を含む | 指示書に明記なし（月足パーフェクトオーダー） | 新ロジックの月足判定は**確定足のみ**で行う（既存は変えない） |

## 8. 実装上の制約（先に共有しておきたいこと）

- **この作業環境からは Yahoo Finance に接続できない**（ネットワーク設定で拒否されている）。そのため、
  - 1章の既知日付（2016-01-20 / 2018-12-25 / 2020-03-09）など**実データを使うテスト**は、ここでは実行できない。
  - 対応案: (a) テスト用ワークフローを追加して GitHub Actions 上で実データテストを回す、(b) 環境のネットワーク設定で `query1.finance.yahoo.com` / `query2.finance.yahoo.com` / `fc.yahoo.com` を許可してもらう、(c) 一度 Actions で取得した日経平均の日足をテスト用フィクスチャとしてコミットする（数百KB）。
- 業績の「発表日」は yfinance では安定して取れないことが多いので、バックテストでは指示書どおり「決算期末から3か月遅らせる」方式が基本になる見込み。
- 業績は yfinance の仕様上、通期4期・四半期5期程度しか取れないため、条件Dの「全期で前年比プラス」は最大でも3回分の前年比比較になる。
